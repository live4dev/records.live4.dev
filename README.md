# records.live4.dev

Статический архив музыкальных записей из [@records_live4dev](https://t.me/records_live4dev).
Интерфейс состоит из видеокаталога с поиском, тегами и страницей просмотра,
аудиоплейлиста справа и общего аудиоплеера. На небольшом экране плейлист
перемещается под каталог. Запуск видео приостанавливает аудио и наоборот.

## Локальный просмотр

```bash
python3 tools/preview.py
```

Откройте <http://127.0.0.1:8000>. Сервер поддерживает HTTP Range: большие видео
и аудиофайлы можно перематывать без скачивания всего файла. Другой порт:
`python3 tools/preview.py --port 8773`.

Сборщик и npm-зависимости не нужны. Открывайте сайт по HTTP, чтобы браузер
мог загружать JSON-каталог.

## Структура архива

```text
content/
  video/                  # исходные видео, постеры JPEG, JSON/TXT с подписями
  audio/                  # исходные аудио/голосовые и звук из видео, JSON/TXT
  archive-manifest.json    # история канала, сведения об импорте и проверках
data/
  records.json            # каталог сайта
  import-state.json       # состояние повторного импорта
tools/
  telegram_import.py      # полный импорт через Telegram MTProto
  telegram_desktop_import.py # импорт штатного JSON-экспорта Telegram Desktop
  preview.py              # локальный просмотр с поддержкой перемотки
```

Подписи сохраняются полностью, с переносами строк и хештегами. Для записей
из альбома без своей подписи сохраняется общая подпись альбома; поле
`caption_original` отдельно хранит собственный исходный текст сообщения.
Карточка содержит дату, длительность и ссылку на оригинальную публикацию.

Записи с `availability: "pending"` и `file: null` пока содержат только
сохранённые метаданные. Сайт не пытается воспроизводить отсутствующие файлы.
Полнота прочитанной истории и полнота скачанных медиа — отдельные показатели.

Аудиоверсия видео имеет отдельный идентификатор с суффиксом `:audio` и
`source_video_id`. Звук AAC извлекается в M4A без повторного кодирования;
для несовместимых форматов используется MP3. В режиме `--video-audio-only`
новые видео служат временным источником: после успешного извлечения звука
они удаляются, а карточка, обложка, описание и ссылка на Telegram остаются.
Уже сохранённые в архиве видео этот режим не удаляет.

## Полный импорт из Telegram

Требуются Python, FFmpeg/FFprobe и пользовательская Telegram MTProto-сессия
с доступом к каналу. Получите `api_id` и `api_hash` на
<https://my.telegram.org>, затем создайте локальную сессию:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python tools/create_telegram_session.py
```

Перед созданием сессии и импортом задайте `TELEGRAM_API_ID` и
`TELEGRAM_API_HASH`, затем `TELEGRAM_SESSION` в окружении. Сессия и API hash
являются секретами; не добавляйте их в Git и не публикуйте в файлах сайта.

```bash
python tools/telegram_import.py --full-history --audio-only --min-duration-seconds 60
python tools/telegram_import.py --refresh --audio-only --min-duration-seconds 60
TELEGRAM_MAX_FILE_MB=1100 python tools/telegram_import.py --refresh --video-audio-only --min-duration-seconds 60
python tools/telegram_import.py --dry-run
```

По умолчанию используется только канал `records_live4dev`, история и размер
файлов не ограничены. `--full-history` читает всю историю,
`--refresh` повторно проверяет публикации, изменения подписей и недостающие
файлы. Существующие скачанные файлы используются повторно.
Ошибка загрузки или конвертации не отмечает запись как успешно обработанную;
повторный запуск продолжает импорт.

Необязательные переменные:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `TELEGRAM_CHANNELS` | `records_live4dev` | Источник; поддержан только этот канал |
| `TELEGRAM_HISTORY_LIMIT` | `0` | Глубина первого чтения; `0` — вся история |
| `TELEGRAM_MAX_FILE_MB` | `0` | Лимит размера; `0` — без ограничения |

`--video-audio-only --min-duration-seconds 60` добавляет в плейлист звук из
видео длиннее минуты, не превращая видеокаталог в многогигабайтный архив.

Положительный лимит размера, если задан, вызывает явную ошибку на превышении;
большие файлы не пропускаются как якобы обработанные.

## Импорт экспорта Telegram Desktop

В меню нужного канала выберите **Export chat history**. Выберите формат JSON,
всю историю, видео, аудиофайлы и голосовые сообщения. Поставьте максимальный
лимит размера файлов и сохраните экспорт, например, в
`content/telegram-export`. Затем:

```bash
python3 tools/telegram_desktop_import.py content/telegram-export/result.json
python3 tools/telegram_desktop_import.py content/telegram-export/result.json --audio-only --min-duration-seconds 60
```

Импорт сверяет канал, идентификаторы сообщений и размеры оригиналов, сохраняет
подписи и создаёт аудиоверсии и постеры. По умолчанию исходники перемещаются
из экспорта в архив, чтобы не хранить две копии больших видео. Добавьте `--copy`,
если нужно оставить исходный экспорт целиком. `--dry-run` проверяет доступность
файлов без изменений. `--audio-only --min-duration-seconds 60` ограничивает
импорт самостоятельными аудиозаписями строго длиннее одной минуты, не удаляя
остальную сохранённую историю канала. Экспорт из другого канала отклоняется.

## GitHub Actions и публикация

Существующий `.github/workflows/import-telegram.yml` требует тех же трёх
Telegram secrets в настройках репозитория. Workflow сначала загружает
самостоятельные аудиозаписи длиннее минуты, затем тремя потоками извлекает
звук из длинных видео. По умолчанию исходное аудио ограничено 250 МБ, а
временное видео — 1100 МБ; значения можно изменить переменными
`TELEGRAM_MAX_FILE_MB` и `TELEGRAM_VIDEO_MAX_FILE_MB`. При превышении workflow
завершается с ошибкой и не выдаёт неполную выгрузку за полный архив.

Полный набор исходных видео канала занимает примерно 9 ГиБ, поэтому рабочий
режим сайта хранит для них обложки, описания и компактные аудиодорожки. Если
понадобится публиковать сами видео, потребуется хостинг или объектное хранилище,
рассчитанное на этот объём. `CNAME` сохраняет адрес `records.live4.dev`;
локальное создание архива само по себе не меняет DNS и не публикует сайт.
